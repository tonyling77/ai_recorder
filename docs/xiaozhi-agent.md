# 小智智能体：把录音变成纪要

小智通道把录音推给云上的智能体，**智能体的回答就是那条纪要**。

板子不再追问了。追问在官方云上只会被当成「唤醒词」：服务器回一个空的
`alert`，然后等音频，而板子不会再发音频，于是六十秒沉默，没有卡片。
追问也把录音笔变成了对话，而录音笔不是对话。

所以这条链路成立的条件只有一个：**你的智能体被配置成「输入是会议录音，
输出是纪要」**。这一步由使用者自己做，板子不替你决定。

## 怎么配

1. 在 xiaozhi.me 上新建（或打开）你的智能体。
2. 把「角色设定 / 人设」写成下面这段。
3. 板子第三页 → 通道 → 小智 → 按屏幕上出现的 6 位验证码绑定到这个智能体。
4. 录一段话，录音结束后按 Upload。

## 人设 / 系统提示词

```
你是一个会议纪要助手。用户发给你的是一段会议录音的转写文本。

请把它整理成一条会议纪要，并且只输出下面这几行，每行一个字段，字段名和值之间用一个空格：

id <编号>
issued <会议时间，形如 2026-11-15 14:30>
title <一句话标题>
conclusion <结论，一句话>
todo <待办事项；有多条就写多行，每行都以 todo 开头>

规则：
- 只输出上面这些行，开头和结尾都不要加别的话。
- 不要用引号、编号列表或者 Markdown 的标题。
- 没有结论或者没有待办时，那一行写「无」。
- 待办最多四条。
```

## 板子怎么读这份回答

板子读的是回答里的**字段名**：

- 找到 `id ` 开头的一行 → 纪要的编号
- 找到 `title ` 开头的一行 → 标题
- `issued ` → 时间，`conclusion ` → 结论，`todo ` → 待办（最多 4 条）

字段在一行里挨着排也行，板子认得出来（`id 1 issued 2026-11-15 14:30 title
周会 conclusion 定了 todo 发纪要` 一样能用）。分开写更清楚。

板子先读**说出来**的那份，读不出卡片才退回智能体写的原文。所以提示词里
不用管标点，智能体写出来的原文一定是对的。

## 怎么知道它成了

固件的日志（串口，`iris logs`）会说清楚：

```
Xiaozhi answer received, the server transcribed 128 bytes
Xiaozhi card reply id 30eda0f452c0-9001 issued ... title ... complete 1
Xiaozhi upload succeeded card ...
```

- `complete 1` → 卡片齐了，板子上的「纪要已收到」。
- `complete 0` 或者 `No card came back` → 回答里没有那五个字段，多半是人设
  没写对，或者智能体答成了聊天。

板子读不出来的另一个原因，是智能体把 `id` 说成了「I D」之类。这种情况下
智能体写的原文里有字段，板子会退回原文，所以一般还是能救回来。

## 录完就上传，不是对话

小智通道的流程只有一轮：录音 → 推上去 → 智能体回答 → 板子把回答读成纪要。

板子上看到的阶段是：

| 阶段 | 意思 |
| --- | --- |
| 正在打包 | 录音在切片 |
| 正在上传 | 音频在推给服务器 |
| 正在整理 | 等智能体把纪要写完 |
| 纪要已收到 | 卡片齐了 |
| 纪要未完成 | 没拿到字段，看日志 |
